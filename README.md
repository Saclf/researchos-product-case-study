# ResearchOS｜科研文献阅读助手

ResearchOS 是一款面向科研文献阅读场景的 Windows 桌面应用，将 PDF 阅读、AI 辅助理解、选中文本翻译、术语整理和阅读记录组织在同一工作区。

> **本仓库是产品作品集展示，不是应用源码或可执行程序发布。** 仓库不包含 EXE、源代码、依赖包、API Key、配置文件、数据库或用户日志。

## 产品问题与工作流

科研文献阅读通常需要在 PDF 阅读器、翻译工具和术语记录之间切换，容易打断阅读过程。ResearchOS 尝试把这些步骤组织成连续流程：

**打开文献 → 阅读与定位 → 获取辅助解释或翻译 → 保存术语或翻译 → 继续阅读。**

这是一项产品设计目标；是否减少切换、提升理解或改善知识留存，仍需要独立的用户研究和测量，本文不声称已取得量化收益。

## 稳定版功能范围

本作品集以 **ResearchOS v0.1.1** 为展示基线。当前展示的功能包括：

- **PDF 阅读：** 目录、翻页、缩放、文本搜索与选择、内部链接定位。
- **AI 辅助理解：** 文献分析与摘要入口，模型服务由用户配置。
- **学术翻译：** 选中文本翻译、成功结果缓存。
- **知识积累：** 术语本、用户主动保存的翻译记忆及历史检索。
- **阅读工作区：** 最近阅读、阅读位置恢复和文献库。

## 高层技术结构

- **桌面交互：** Python、PySide6。
- **PDF 阅读与文本提取：** Qt PDF、PyMuPDF。
- **AI 分析与翻译：** 用户配置的 OpenAI 兼容 HTTP 接口。
- **本地数据：** SQLite。
- **凭据管理：** Windows Credential Manager。

## 产品思考

### 将功能组织在阅读流程中

阅读、解释、翻译和知识保存围绕文献任务组织，而不是将 AI 功能作为孤立聊天入口。实际体验收益仍需通过用户任务验证。

### 区分翻译缓存与主动保存

成功翻译缓存用于复用结果；Translation Memory 用于保存用户主动选择保留的翻译。自动产生过结果不代表用户已经决定收藏或掌握该知识。

### 明确 AI 的能力边界

稳定版分析与摘要入口最多传入前 **30,000 个字符**，不能据此宣称长论文全文分析已通过验收。模型输出需要人工核对；接口返回不等于科研正确性得到验证。

## 验证与已知限制

本作品集截图和短视频来自用户实际运行的 v0.1.1 演示，展示了 PDF 阅读、AI 文献概览、课题关联建议和选中文本翻译。它们属于有限的人工演示证据，不等于完整回归测试、兼容性测试、性能测试或科研正确性验证。

已知限制包括：

- 分析和摘要入口最多传入前 30,000 个字符。
- 分析/摘要请求可能阻塞界面。
- 模型输出可能存在遗漏或错误，需要对照原文检查。
- OCR、完整科研笔记系统、分块证据和独立 Quick/Deep 等后续方向，不属于本作品集展示的 v0.1.1 稳定功能。
- 目前没有可公开支持普遍效率提升、用户规模或科研正确率的量化数据。

AI 功能会把提取的文本发送到用户配置的模型服务商，并可能产生费用。使用者应先确认服务商的数据处理条款、输入内容的保密要求和自己的费用限制。**本仓库不包含任何 API Key。**
